# 变更（Changes）

逐块审查 Agent 在本会话里改过的文件，接受或撤销每一处改动，并把工作区对齐到某个 Git commit / SVN 版本。

本插件只提供两处变更提示：

| 表面 | 位置 | 作用 |
|---|---|---|
| 待审条 | 输入框上方 | 唯一的变更提示。显示待审文件数、增删行数，支持全部保留 / 全部撤销与逐文件处置 |
| 变更面板 | 右侧栏「变更」页 | 逐块审查、切换审查基线、整区回退 |

会话流里不出现本插件绘制的任何变更卡片。

## 待审条

Agent 改动文件后，输入框上方出现一条：

```
▤  3 个文件待审查 ▾   +128 −12                     全部撤销  全部保留
```

- 点图标或文案展开文件清单；每行可直接「保留 / 撤销」。
- 点某一行 → 右侧「变更」页打开并定位到该文件。
- 「全部撤销」会二次确认，并把每个文件写回它本轮改动前的内容。
- 待审文件数归零后，整条提示消失。

**待审**的判定：该文件的最新改动还没有任何决策记录。文件再次被改动时（新的一轮），它会重新变成待审。

## 变更面板

右侧栏 → 顶部的页面目录（`+`）→「变更」。

- 左栏：本会话改动的文件（路径 + 增删行数），已处理置灰。
- 右栏：当前文件最近一轮的改动块，顶部固定「接受 / 拒绝」，作用于第一个待审块；处理后自动推进并滚动到位。
- 工具条：全部接受 / 全部拒绝 / 整区回退。
- 基线：`会话快照`（默认）/ `Git commit` / `SVN 版本`。切到 VCS 基线后左栏变为版本点，选中版本点可看它会带来的文件改动。

## 版本控制

工作目录是 Git 仓库或 SVN 工作副本时可用：

- 列出最近 20 个版本点。
- 「整区回退」分别执行 `git reset --hard <ref>` / `svn update -r <rev>`，把工作区强制对齐到该版本，**丢弃其后的所有改动**，需二次确认。

## 配置

插件详情页有一个开关：

**DSH 原生交付卡片**（默认：隐藏）

隐藏 DSH 原生的会话内「已编辑 N 个文件」变更卡片，让待审条成为唯一的变更提示。该卡片与「交付卡片」「正文文件提及」「原生变更审查 tab」同属原生包 `dsh-client-ui-deliverables`，关闭时会一并隐藏；本插件的待审条与右侧面板不受影响。

- 改动后本插件重启一次即生效，无需重启应用。
- 停用或卸载本插件后原生卡片自动恢复。
- 开关的值随本插件自己的配置行保存；运行时的加载状态切换只在内存中进行，不会改写你的 `cordis.patch.yml`，也不修改任何其他插件。

## 已知限制

1. 改动数据会落盘到 `$DSH_HOME/dsh-changes/state.json`（默认 `~/.dsh/dsh-changes/state.json`），重启 DSH 后待审条与 Diff 面板仍然保留。只有插件运行期间记录的回合会被存下来；装本版本之前已丢失的回合找不回来。保留规模：每会话最近 20 轮、最多 12 个会话、整体上限 8 MB。
2. 每个文件只展示并处置它**最近一轮**的改动。同一文件在更早回合的改动不会被这里撤销，需要时用 VCS 整区回退兜底。
3. 拒绝（撤销）依赖行号精确匹配：文件在记录之后又被其他途径改过，就会显式报「文件已漂移」并拒绝写入，不做猜测。
4. 撤销一个**本轮新建**的文件会把它删除（而不只是清空）；撤销「本轮被删除的文件」暂不支持，需要 VCS 兜底。
5. 二进制文件与超大文件只能「保留」，不能「撤销」。
6. 决策记录会随改动快照一起落盘：刷新页面、插件停用、宿主重启后都保留；点「全部撤销」或做整区回退后，该会话的存档会被清空。
7. 关闭原生卡片等于关闭整个 `dsh-client-ui-deliverables` 包，`present` 工具会回落到通用工具视图。
8. 启动首帧可能短暂闪现原生卡片（该包在组合期默认加载，本插件激活后才按配置关闭）。
